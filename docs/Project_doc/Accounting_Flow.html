3 Action: import — รับข้อมูลจาก HIS

Action นี้รับ array ของ batch objects แล้ว insert ลง PostgreSQL ในครั้งเดียว — เป็น entry point แรกของข้อมูลจาก HIS

1
HIS ส่ง HTTP POST พร้อม JSON body

เรียก endpoint: POST /accounting/import

ต้องมี Authorization header: Bearer token ที่ออกโดย XSUAA (accounting-auth)

2
CAP validate & insert

CAP framework จัดการ validation ตาม schema.cds โดยอัตโนมัติ แล้ว insert ทั้ง Batches, Items, Payments ใน transaction เดียวกัน

3
Response

Return IDs ของ batches ที่ insert สำเร็จ — HIS สามารถเก็บไว้ใช้ track สถานะ

4 Action: postFI — ส่ง FI Document ไป S/4HANA

Mode 1: ส่งทีละ batch

// POST /accounting/postFI
{
  "batchId": "uuid-of-batch"
}

Mode 2: ส่งทั้ง hisDocumentType + วันที่

// POST /accounting/postFI
{
  "hisDocumentType": "RECEIPT_OPD",
  "billDate": "2024-01-15"
}

postFI Flow (Step-by-Step):

1
รับ Parameters และ Route
  • ถ้ามี batchId → ดึง batch นั้นเดียวจาก DB
  • ถ้ามี hisDocumentType + billDate → ดึง Batches ทั้งหมดที่ตรงเงื่อนไข แบบ package loop
2
Package-size Loop (สำหรับ Mode 2)
  • ดึง Batches ทีละ 100 รายการ (package-size)
  • loop จนหมด เพื่อป้องกัน memory overflow เมื่อมีข้อมูลมาก
  • แต่ละ batch → เรียก processBatch(batch)
3
processBatch: เช็ค Skip
  • ดู JournalEntryPostings ของ batch นี้
  • ถ้ามี status = POSTED แล้ว → skip ไม่ส่งซ้ำ
4
ดึง Items จาก DB
  • Query Items ที่ belong to batch นี้
  • รวม fields ที่ต้องใช้: itemCode, netAmount, billingGroup, CO-PA fields ทั้งหมด
5
ดึง GL Mapping จาก central-config (Parallel)

เรียก 5 endpoint พร้อมกันด้วย Promise.all:

  • SAPDocumentTypeMapping — map hisDocumentType → SAP document type
  • DebitCreditIndicator — กำหนด H(Debit)/S(Credit) ตาม line type
  • RevenueGLMapping — map itemCode → revenue GL account
  • CostCenterMapping — map department code → cost center
  • PaymentMethodGLMapping — map paymentMethod → GL account
6
ดึง Payments จาก DB
  • Query Payments ที่ belong to batch นี้
  • ใช้สร้าง payment lines ใน SOAP
7
Group Items by billingGroup
  • แต่ละ billingGroup → 1 Journal Entry ใน S/4HANA
  • วิธีนี้ทำให้ 1 batch สามารถมีหลาย JE ได้
8
ส่ง SOAP ต่อ billingGroup
  • เรียก postJournalEntry(billingGroup, items, payments, configs, batchData)
  • Function นี้อยู่ใน srv/s4h-journal.cjs
9
บันทึกผลลัพธ์
  • สำเร็จ: insert JournalEntryPostings (status=POSTED, JE Document Number) + Messages
  • ล้มเหลว: insert JournalEntryPostings (status=ERROR) + Messages (error details)
  • Items.fiPosting ถูก update ให้ชี้ไปยัง JournalEntryPosting ที่สร้าง
5 Central Config Client — ดึง GL Mapping
⚡ ทำไมต้อง XSUAA? central-config-srv เป็น service แยก — accounting-srv ต้องแสดงตัวตน (authenticate) ก่อนเรียก OData API โดยใช้ token จาก shared XSUAA instance (central-config-auth)

Token Flow

  1. อ่าน credentials จาก env vars (CENTRAL_CONFIG_CLIENT_ID, CENTRAL_CONFIG_CLIENT_SECRET, CENTRAL_CONFIG_TOKEN_URL)
  2. POST ไป XSUAA token endpoint: grant_type=client_credentials
  3. Cache token ไว้ (จนหมดอายุ) เพื่อไม่ต้องขอใหม่ทุกครั้ง
  4. ใส่ Bearer token ใน Authorization header ของ OData request

5 Tables ที่ดึง

  • SAPDocumentTypeMapping — hisDocumentType → SAP Doc Type
  • DebitCreditIndicator — กำหนด D/C per line type
  • RevenueGLMapping — itemCode → Revenue GL
  • CostCenterMapping — dept code → Cost Center
  • PaymentMethodGLMapping — paymentMethod → GL

Env vars ที่ต้องใช้ (มาจาก VCAP_SERVICES หรือ set เอง):

# ต้องมีใน environment ก่อนรัน
CENTRAL_CONFIG_CLIENT_ID=sb-central-config-...
CENTRAL_CONFIG_CLIENT_SECRET=...secret...
CENTRAL_CONFIG_TOKEN_URL=https://....authentication.ap11.hana.ondemand.com/oauth/token
CENTRAL_CONFIG_URL=https://central-config-srv.cfapps.ap11.hana.ondemand.com
✗ ข้อผิดพลาดบ่อย: central-config credentials not found — เกิดเมื่อ env vars ไม่ได้ถูก set ในเทอร์มินัลเดียวกับที่รัน cds serve
6 S4H Journal Builder (s4h-journal.cjs)

ไฟล์นี้รับผิดชอบสร้าง SOAP payload และส่งไป S/4HANA — ใช้ .cjs เพราะ mixed module environment

buildItemLines(hisDocumentType, options)

สร้าง Journal Entry line items สำหรับรายการค่าบริการ

Line TypeGL AccountD/Cเงื่อนไข
Revenueจาก RevenueGLMapping (itemCode)Creditทุก document type
DiscountGL บัญชีส่วนลดDebitไม่มีใน CREDIT_NOTE / DEBIT_NOTE
Cost Centerจาก CostCenterMappingDebitถ้ามี cost center mapping
ReconcileGL reconciliationDebit/Creditbalance entry
ℹ CO-PA fields ถูก attach ไปทุก line: YY1_HospitalNumber, YY1_VisitNumber, YY1_CoverageCode, YY1_PatientGroup, YY1_MarketChannel, YY1_PatientType, YY1_OrderCategory, YY1_OrderSubCategory, YY1_RequestDeptCode, YY1_PerformDeptCode
buildPaymentLines(options)

สร้าง payment line items จาก Payments array

  • Map paymentMethod → GL account จาก PaymentMethodGLMapping
  • แต่ละ payment record = 1 line ใน JE
  • รองรับ: CASH, TRANSFER, EDC, QR, VOUCHER, DEPOSIT
buildRequestBody(options)

ประกอบ SOAP XML JournalEntryCreateRequest ทั้งหมด

  • รวม item lines + payment lines
  • ใส่ header: CompanyCode, DocumentDate, PostingDate, Currency, SAP DocumentType
  • ใส่ ProductTaxItem: TaxCode=O0, TaxItemClassification=MWS (สำคัญ! ขาดไปจะ error)
  • Wrap ด้วย SOAP envelope ที่ถูกต้อง
postJournalEntry(billingGroup, items, payments, configs, batchData)

Orchestrate ทั้งหมด: สร้าง payload → ส่ง SOAP → parse response

  1. เรียก buildItemLines + buildPaymentLines
  2. เรียก buildRequestBody
  3. ส่ง HTTP POST ไป S/4HANA ผ่าน Destination service URL
  4. Parse SOAP XML response
  5. Return: { status, journalEntryDocNumber, companyCode, year, messages[] }
7 SOAP Structure ที่ส่งไป S/4HANA

Interface: JOURNALENTRYCREATEREQUESTCONFI — ตัวอย่าง structure ของ SOAP body

<!-- SOAP Envelope -->
<soapenv:Envelope xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
                  xmlns:glob="http://sap.com/xi/SAPGlobal20/Global">
  <soapenv:Body>
    <glob:JournalEntryCreateRequest>
      <MessageHeader>
        <ID>uuid-v4</ID>
        <CreationDateTime>2024-01-15T10:30:00Z</CreationDateTime>
      </MessageHeader>

      <JournalEntry>
        <!-- Header -->
        <CompanyCode>1000</CompanyCode>
        <DocumentDate>2024-01-15</DocumentDate>
        <PostingDate>2024-01-15</PostingDate>
        <DocumentCurrency>THB</DocumentCurrency>
        <AccountingDocumentType>DR</AccountingDocumentType>

        <!-- Item Lines (Revenue + Discount + Payment) -->
        <Item>
          <GLAccount>4001001</GLAccount>
          <DebitCreditCode>S</DebitCreditCode> <!-- S=Credit -->
          <TransactionCurrencyAmount>500.00</TransactionCurrencyAmount>
          <TaxCode>O0</TaxCode>
          <!-- CO-PA Extension Fields -->
          <YY1_HospitalNumber>HN-12345</YY1_HospitalNumber>
          <YY1_VisitNumber>VN-67890</YY1_VisitNumber>
          <YY1_CoverageCode>CASH</YY1_CoverageCode>
          <YY1_PatientGroup>OPD</YY1_PatientGroup>
          <YY1_MarketChannel>WALK_IN</YY1_MarketChannel>
          <YY1_PatientType>NEW</YY1_PatientType>
          <YY1_OrderCategory>CONSULT</YY1_OrderCategory>
          <YY1_OrderSubCategory>GENERAL</YY1_OrderSubCategory>
          <YY1_RequestDeptCode>OPD</YY1_RequestDeptCode>
          <YY1_PerformDeptCode>MED</YY1_PerformDeptCode>
        </Item>

        <!-- ProductTaxItem (สำคัญมาก! ขาดไม่ได้) -->
        <ProductTaxItem>
          <TaxCode>O0</TaxCode>
          <TaxItemClassification>MWS</TaxItemClassification>
          <TransactionCurrencyTaxAmount>0</TransactionCurrencyTaxAmount>
        </ProductTaxItem>

      </JournalEntry>
    </glob:JournalEntryCreateRequest>
  </soapenv:Body>
</soapenv:Envelope>
✗ ข้อผิดพลาดที่พบบ่อย: Tax statement item missing for tax code O0 — เกิดเมื่อ ProductTaxItem ไม่ได้ถูกส่ง หรือ TaxItemClassification ไม่ใช่ MWS
8 JournalEntry Status & Messages

POSTED — สำเร็จ

  • S/4HANA ออก JE Document Number
  • บันทึก JournalEntryDocumentNumber, CompanyCode, Year
  • Items.fiPosting ชี้ไปยัง JournalEntryPosting นี้
  • Messages ประกอบด้วย msgType=S และ/หรือ I

ERROR — ล้มเหลว

  • S/4HANA reject หรือ SOAP call ล้มเหลว
  • JournalEntryDocumentNumber = null
  • Messages มี msgType=E พร้อมรายละเอียด
  • Batch ยังสามารถ retry ได้ (เพราะ skip check ดูแค่ POSTED)

ประเภท Message (msgType):

msgType ความหมาย ตัวอย่าง Message Action ที่ควรทำ
S Success Document 1234567890 created in company code 1000 ไม่ต้องทำอะไร — สำเร็จ
I Information Balances updated for cost center CC001 รับทราบเฉยๆ — ปกติ
E Error Tax statement item missing for tax code O0 ต้องแก้ payload แล้ว retry
W Warning Exchange rate for date not found, using standard rate ตรวจสอบ แต่อาจไม่กระทบ
✓ Retry Logic: batch ที่ status=ERROR สามารถ call postFI ซ้ำได้เลย — เพราะ skip check เช็คเฉพาะ POSTED เท่านั้น batch ERROR จะถูก process ใหม่
⚡ Known Error: KSCHL is empty — เกิดจาก SAP ยังไม่ได้ config ConditionType สำหรับ tax code O0 — ต้องให้ SAP Basis admin เข้าไปตั้งค่าใน customizing table ไม่ใช่ปัญหาของ code
