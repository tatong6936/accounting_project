ภาพรวมกระบวนการ Post FI
postFI คือ action ที่รับ Batch จาก CAP → รวมยอดตาม billingGroup → ส่ง SOAP ไปยัง S/4HANA Cloud → บันทึกเลขเอกสาร FI กลับใน JournalEntryPostings
1
รับ Request
POST /postFI พร้อม batchId หรือ hisDocumentType + billDate — ดึง batch จาก PostgreSQL
2
ตรวจ Skip
ถ้า batch นั้นมี JournalEntryPosting อยู่แล้ว → ข้าม (ไม่ post ซ้ำ)
3
Group Items ตาม billingGroup
Items ที่มี billingGroup เดียวกัน → รวมเป็น 1 Journal Entry — กลุ่มที่ไม่ระบุ billingGroup จะใช้ "DEFAULT"
4
ส่ง SOAP ต่อ group
เรียก JournalEntryCreateRequestConfirmation_InAsync ไปยัง my442293-api.s4hana.cloud.sap ต่อ 1 group — ถ้า group ใด fail ยัง post group อื่นต่อได้ (partial success)
5
บันทึกผลลัพธ์
Insert JournalEntryPostings + JournalEntryMessages ลง PostgreSQL, update fiPosting_ID ใน Items

Response & Status
RES
postFI Response
format: string สรุปผล
›
HTTP 200 — Success (มีหรือไม่มี error บางส่วน)
// ทุก batch post สำเร็จ
"postFI done — processed: 2, skipped: 0, failed: 0, FI docs: 3"

// batch หนึ่งถูก skip (post ซ้ำ)
"postFI done — processed: 1, skipped: 1, failed: 0, FI docs: 2"

// มี error บางส่วน (partial success)
"postFI done — processed: 1, skipped: 0, failed: 1, FI docs: 1 | ERRORS: Batch xxx group DEFAULT: Not enough budget available."
ความหมายของ field ใน response
Fieldความหมาย
processedจำนวน batch ที่ดำเนินการเสร็จ (มี FI doc อย่างน้อย 1 group)
skippedจำนวน batch ที่ข้าม (มี JournalEntryPosting อยู่แล้ว)
failedจำนวน batch ที่ล้มเหลวทั้งหมด (ทุก group fail)
FI docsจำนวน Journal Entry ที่สร้างใน S/4HANA สำเร็จ
ERRORSรายละเอียด error (มีถ้ามี group ที่ fail)
HTTP Error Codes
400ไม่ระบุ batchId หรือ hisDocumentType+billDate ไม่ครบ
404batchId ที่ระบุไม่พบใน DB

Error & Troubleshoot
ERR
Error Cases ที่พบบ่อย
›
Errorสาเหตุวิธีแก้
PSM_S4C_FM_AVC013 Budget ไม่พอใน Cost Center 11AA-30000 / Fund 11AA010003 เพิ่ม budget ใน S/4HANA Fiori App หรือเปลี่ยน Cost Center
AccountingDocument: "0000000000" S/4HANA ไม่สร้างเอกสาร — มักเกิดจาก budget error หรือ config ผิด ดู Log.Item ใน SOAP response เพื่อหา error จริง
Batch xxx: no items Batch ไม่มี Items เลย ตรวจสอบว่า import items ครบก่อน post FI
skipped: 1 Batch ถูก post ไปแล้ว (มี JournalEntryPosting อยู่แล้ว) ปกติ — ไม่ใช่ error, ป้องกัน double-posting
HTTP 400 ไม่ส่ง batchId หรือ hisDocumentType+billDate ตรวจ request body ให้ครบ
HTTP 404 batchId ไม่มีในระบบ ตรวจ ID ที่ส่งมาใน GET /Batches ก่อน

Logic ภายใน postFI
CODE
กฎสำคัญของ postFI handler
srv/accounting-service.js
›
กฎรายละเอียด
ป้องกัน double-post ตรวจ JournalEntryPostings ก่อน — ถ้ามีอยู่แล้ว skip ทันที
Group by billingGroup Items ที่ billingGroup เดียวกัน รวมยอด netAmount → 1 Journal Entry — ถ้าไม่มี billingGroup ใช้ "DEFAULT"
SOAP outside DB transaction เรียก S/4HANA SOAP ก่อน — ได้ผลสำเร็จแล้วค่อย insert ลง DB (ไม่ rollback SOAP)
Partial success ถ้า group ใด SOAP fail → เก็บ error แต่ยัง post group อื่นต่อ
DocumentReferenceID ใช้ accountingDocumentNumber ของ batch (ตัดให้ ≤16 chars) + "-" + seqNo ต่อ group
